## 本轮实现

1. 从核定 main 创建 `codex/integrate-systems`。
2. 三次不带 `--squash` 的 `git subtree add`，逐次记录源树、导入树、导入提交与祖先关系。
3. 独立 Vue 门户，普通 HTML 链接导航，三个完整系统名称、简介、维护状态。
4. 固定 `/relation/`、`/extraction/`、`/crawler/`；配置失效或变化时关闭业务转发，维护 API 明确返回 503。
5. 配置统一驱动门户、Vite 网关、Nginx 配置生成及启动计划；维护系统不启动、不构建、不初始化数据。
6. 基于精确进程身份的本地启停、日志隔离、来源验证、自动化与浏览器检查、独立克隆复现。

保留每个系统原始目录、认证、数据存储和依赖版本。没有建立父 POM、npm workspace、微前端、单点登录、跨系统数据流水线或模拟业务后端。

## 环境适配

本机未找到 Nginx。第一阶段 `Demo` 用 Vite preview 提供构建产物及相同隔离中间件，`Development` 用 Vite 开发服务；二者只绑定 127.0.0.1、同用配置中的端口并互斥。Vite preview 仅作为本地演示入口，不视为生产服务器。

Nginx 采用受版本控制的生成器，从当前接入配置生成 `.local/nginx/nginx.conf`。模板逻辑已测试；Nginx 本体的 `-t` 和运行验收未执行。以后使用 Nginx 时必须生成、检查、启动，并在状态变化后重新生成和加载；不能假定运行中的 Nginx 会自动读取 JSON。

## 阶段验收

- 第一阶段：来源完整、历史保留、门户独立安装/构建/启动、维护页和 API 隔离、启停安全、独立克隆复现。
- 第二阶段：对子系统分别验证构建、认证、CSRF、路径、静态资源、下载、独立数据库、Neo4j 和核心业务，再启用。
- 一个系统的业务失败不阻止本轮门户；保持有效测试，明确记录未执行项。

原方案中的“Ye 只有启动类”已被实施开始时的远端源码推翻；实施中远端又回到旧提交。本轮冻结点及后续同步限制见 [集成基线](integration-baseline.md)。
